# Mellow-Player Surface

Shirone 博客 `::artplayer` 嵌入之上的 M3E 播放表面，以及它背后那道引擎接缝。

## 语言

**表面 (Surface)**：
读者实际看到并操作的那一层——舞台、控制栏、进度与音量滑杆、诊断面板。它只认 `MediaEngine` 接口，不知道背后是谁在解复用。
_Avoid_: 播放器组件、UI 层

**引擎 (Engine)**：
驱动媒体的一整套实现，落在同一个 `MediaEngine` 接口后面。目前两个：`native`（媒体元素）与 `mellow`（Mellow-Player 的有界 Range / WebCodecs 管线）。
_Avoid_: 播放内核、后端

**引擎模块 (Engine Module)**：
由 `engineUrl` 指向的一份 ES 模块产物，其命名空间导出 `HeadlessPlayer`。它是本仓库与 Mellow-Player 之间**唯一**的耦合面；源码依赖刻意不存在，所以对方仓库怎么演进都不会牵扯主题的构建。
_Avoid_: 依赖、SDK、包

**意图 (Intent)**：
读者明确表达的播放意愿——按下播放。引擎模块只在此时被解析；在此之前页面上不存在任何引擎字节。
_Avoid_: 惰性加载、懒加载

**能力 (Capability)**：
引擎声明自己能做与不能做的事（有界 Range、画布渲染、关键帧寻址、可变速）。表面据此**隐藏**不支持的控件，而不是渲染一个按不动的按钮；误用会抛 `EngineCapabilityError`。
_Avoid_: 特性开关、支持列表

**可达性 (Reachability)**：
源站是否允许引擎读它。引擎用 `fetch` 读媒体，媒体元素不需要 CORS，所以「能播」不等于「读得到」——云盘当源站时这正是分界线。容器决定**能不能**交给引擎，可达性决定**该不该**交给它。
_Avoid_: 可用性、连通性、CORS 检查

**探测 (Probe)**：
判定可达性的那一次单字节有界 Range 读取（`bytes=0-0`）。只接受 `206`：`200` 说明源站忽略了 Range 并开始整片交付，那正是引擎要拒绝的源。按 origin 缓存，一次会话里同源只问一次。
_Avoid_: 健康检查、预热、握手

**标签 (Labels)**：
表面渲染的每一句用户可见文案。本插件不持有任何一条：`labels` 必填，缺失即拒绝安装。
_Avoid_: 文案、i18n 字典

**增强 (Enhancement)**：
把 SSR 输出的原生播放器换成表面的那一步。它是渐进式的：服务端输出的 `<video>` 在无 JS、增强失败、引擎不可达时仍然是完整可用的播放器。
_Avoid_: 水合、替换、劫持

**着陆点 (Landing)**：
一次 seek 实际落在哪个关键帧上。有界 Range 引擎从关键帧恢复解码，所以目标时间与着陆时间可以不同，`keyframeSeek` 为真的引擎会把两者都报出来。
_Avoid_: 跳转位置

**有界 Range (Bounded Range)**：
形如 `bytes=A-B` 的定长请求，两端都闭合。与浏览器原生媒体栈发出的开放式 `bytes=N-` 相对——后者正是本引擎要绕开的东西。
_Avoid_: 分段请求、分片下载

**舞台 (Stage)**：
表面里承载媒体元素或画布的那块区域。引擎往它里面创建自己的元素，其余部分（控制栏、覆盖层、状态提示）都在它之外，因此它们不会随全屏一起被留在屏幕外。
_Avoid_: 容器、视口、播放区
